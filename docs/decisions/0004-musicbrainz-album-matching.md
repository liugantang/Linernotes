# 0004 · MusicBrainz 补全：按专辑文本匹配，不做 AcoustID

> 2026-09-30 · 阶段 7

## 背景

阶段 7 的目标是给曲库补齐年份、专辑艺人、音轨号等缺失字段和封面。原计划是用声学指纹经 AcoustID 查到 recording，再归到 release。
实际情况：

- AcoustID 需要单独申请应用 key，且按曲目逐个查询，一万多首的曲库要几个小时；查到的是 recording，还得再从多个 release 中选一个。
- 本地曲库以“一个目录一张专辑”为主，`albums` 实体已经把曲目分好组，专辑名、艺人名大多可用，缺的是年份、编号这类字段。
- 按曲目各自匹配容易把同一张专辑的曲目匹配到不同 release（原版、精选、数字版），补出互相矛盾的年份和编号。

## 决定

1. **本阶段不做 AcoustID**。7.1 算好的 Chromaprint 指纹只用于本地重复识别（7.8）。
2. **以专辑为单位文本匹配**（`butler.mb_match`）：
   - 用“专辑名 + 专辑艺人”搜索 release。查询用**词项**写法 `release:(...) AND artist:(...)`，不用短语 `release:"..."`：
     实测 `宝物 (24bit/96kHz)`、`[High-Resolution]` 这类带噪声的专辑名用短语查询搜不到。
   - 候选：分数 < 70 的丢弃；同一 release group 且音轨数相同的只留一个（同分时官方发行优先于伪发行）；
     音轨数与本地一致者优先；最多取 3 个详情（MB 限速 1 次/秒，每个专辑约 4 次请求）。
   - 打分（7.3）：整张专辑一起配对，曲目对得分 = 标题相似度与时长的加权，编号一致加分；本地只有部分曲目时只轻微扣分。
     标题已损坏（乱码无法修复）的曲目只按时长与编号配对。
   - 最高分 < 0.75 → 不匹配；前两名分差 < 0.05 且补全结果不同 → 歧义，只记录不补。
3. **只补空字段**，生成修正提议（`CorrectionKind::MbMatch`），用户审核或按阈值自动接受；已有值一律不改。
   例外：乱码修复判定为“需要在线查询”的标题，用 MB 标题替换。DVD、Blu-ray 等视频介质不计入碟数与音轨。
4. **封面**：只为已匹配、没有封面的专辑从 Cover Art Archive 下载（release 没有则用 release group 的），直接设为专辑封面，
   不写回文件；重扫时文件封面优先，没有文件封面则保留在线封面。
5. **LLM 判别歧义（7.4b）暂缓**：真实曲库试跑中出现的歧义都是候选选择的问题（已在 7.4c 修正），
   等用户全量运行后看剩余歧义专辑的数量与类型，再决定是否需要 LLM。

## 后果

- 不需要额外的 API key，只依赖 MB 与 CAA 的公开接口；全量首轮耗时约为“专辑数 × 4 秒”，之后命中本地缓存（30 天）。
- 没有专辑名或专辑名错误的散曲无法匹配；这部分以后再考虑 recording 搜索或指纹。
- 搜索、详情都缓存在 `mb_cache`，匹配结果与 MBID 记在 `mb_album_matches` / `mb_track_matches`，后续的版本识别（7.6）可以直接使用 recording MBID。
