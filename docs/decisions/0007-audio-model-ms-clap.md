# 0007 · 音频理解选型：MS-CLAP 音频编码器 + 信号特征，乐器用线性分类头

> 2026-10-01 · 阶段 9 选型（9.1–9.2）结束时。实验代码在 `spike/audio-eval` 分支，不合入 main。

## 背景

阶段 9 要在本地回答“有没有人声 / 有没有小号、鼓机 / 安静还是燥 / 像不像这首”（F-AUD-01～05），方案不预设（F-AUD-08）。
候选：纯信号特征、PANNs CNN14（AudioSet 分类）、Essentia 预训练模型（discogs-effnet + 乐器 / 人声 / 情绪分类头）、LAION-CLAP（音乐权重）、MS-CLAP 2023。

## 评测方法

- **真值不用人工标注**：用户不是音乐专业，自己标注质量差（试标 12 首即放弃）。改为 agy（Gemini Flash）盲听：每首在 20% / 50% / 80% 处各取 20 s 拼成一段，随机文件名、不给任何元数据，按固定词表输出人声、乐器、energy / valence 三档。
- **单遍 LLM 标签噪声大**：gemini-3.7-flash 与 3.8-flash 各标一遍，乐器除贝斯、合成器外两遍 Jaccard 只有 0.45–0.66。因此以**两遍共识**为真值：都列出 → 正例，都没列 → 负例，分歧 → 该项不计分；energy / valence 取均值。gemini-3.1-pro 在 agy 中听不到音频，不可用。
- **客观真值**：曲库中 101 对“伴奏（instrumental / off vocal / からおけ）+ 同专辑原唱”。LLM 在这些配对上的人声准确率只有 92.6%（3.7）/ 90.4%（3.8），存在明显幻觉（如把儿歌伴奏描述成死核嘶吼）——LLM 标签只能当近似真值，乐器数字要看相对高低，不能看绝对值。
- 样本：分层抽样 90 首（五个候选全跑）；另抽 1000 首，两遍共识覆盖 620 首，只有 PANNs 跑完。为收敛工作量，按用户决定在此停止，不再补跑。
- 每首只分析 3 段 × 10 s（20% / 50% / 80%），嵌入取平均；耗时在 CPU 4 线程下测，含解码。

## 决定

1. **主模型：MS-CLAP 2023 的音频编码器**。一个模型覆盖人声、energy / valence、乐器、相似度（1024 维嵌入）与将来的自由描述检索；最快、许可证干净。
   - 产品运行时只需要**音频编码器**（ONNX）。人声、energy、valence、乐器零样本用到的提示语是固定的，其文本嵌入离线算好随程序发布，C++ 侧不需要 GPT-2 与分词器。
   - 自由描述检索（F-AUD-04，P2）需要运行时文本编码器 + GPT-2 分词器，留到阶段 10 再决定是否做。
   - 备选：ONNX 导出或 C++ 推理走不通时换 LAION-CLAP（文本检索略好，但体积大、慢一倍）。
2. **乐器用线性分类头**：零样本精度约 66%，低于验收的 70%；在 MS-CLAP 嵌入上训练逻辑回归（训练数据 = LLM 共识标签），交叉验证精度 84%。权重只有几 KB，随程序发布，可在曲库变化或标签改进后重训。
   小号 / 萨克斯 / 木管等少见乐器在 620 首共识里只有 0–13 个正例，训练不了分类头，先用零样本提示语打分，效果可能达不到验收线（见“遗留”）。
3. **人声**：MS-CLAP 零样本（或同法训练的分类头）。零样本在 0.5 阈值下准确率只有 69%，排序（AUC 1.0）没问题，阈值需要校准。
4. **energy**：MS-CLAP 提示语分数与响度 / onset 信号特征融合（两者单独约 0.77–0.79），权重在 9.7 用共识标签定；**valence** 只用 MS-CLAP，可靠性一般。
5. **信号特征在 C++ 里自己做，不用 Essentia**：响度与响度范围用已有依赖 libebur128；BPM 与调性的实现在 9.5 另选（Essentia 是 AGPL、multifeature BPM 每首 14 s，太慢）。
6. **不选**：Essentia（模型许可证禁止商用与演绎，无法随 GPL 程序分发；且慢）；PANNs（人声好，但没有文本空间、没有 energy，单独用不够）。
7. **分析量**：每首 3 段 × 10 s（MS-CLAP 取每段中间 7 s），推理约 0.4 s + 解码。1 万首在 4 核 CPU 上约 3 小时（不含 SMB 读文件），满足“一晚完成”。

## 遗留 / 未验证

- CLAP 只在 90 首上测过；620 首上只有 PANNs 的结果。
- “小号、鼓机等明显乐器准确率 ≥ 70%”：鼓机有足够正例，分类头可达；小号 / 铜管缺正例，**没有数据支撑**，阶段验收时如实记录。
- 片段策略（3 × 10 s）与整首分析的差距没测。
- 相似歌曲只做了嵌入，主观效果在 9.11 由用户试听评价。
- MS-CLAP 音频编码器（HTSAT）能否顺利导出 ONNX、C++ 前处理（重采样、梅尔谱）与 Python 的一致性，是 9.3 要验证的主要风险。
